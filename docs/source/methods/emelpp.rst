EmEL++ and EmEL(var)
====================

EmEL++ [mondal2021]_ and EmEL(var) [mohapatra2021]_ are extensions of ELEmbeddings
([kulmanov2019]_). They keep its geometry: a class is an :math:`n`-ball (centre :math:`e_v(C)`
and radius :math:`e_r(C) \ge 0`) and a role :math:`R` is a translation vector :math:`e_v(R)`.
Each normal form has a loss that is zero when the geometric condition holds; the total loss is
their sum, minimised with Adam.

EmEL++
------

Normal forms (margin :math:`\gamma`, all losses also contain the terms
:math:`|\lVert e_v(x) \rVert - 1|` of the embedding vectors they involve):

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Axiom
     - Hinge term (paper equation)
   * - :math:`C \sqsubseteq D`
     - :math:`\max(0, \lVert c - d \rVert + r_c - r_d - \gamma)` (1)
   * - :math:`C \sqcap D \sqsubseteq E`
     - :math:`\max(0, \lVert c-d \rVert - r_c - r_d - \gamma) + \max(0, \lVert c-e \rVert - r_c - \gamma) + \max(0, \lVert d-e \rVert - r_d - \gamma) + \max(0, \min(r_c, r_d) - r_e - \gamma)` (2)
   * - :math:`C \sqsubseteq \exists R.D`
     - :math:`\max(0, \lVert c + r - d \rVert + r_c - r_d - \gamma)` (3)
   * - :math:`\exists R.C \sqsubseteq D`
     - :math:`\max(0, \lVert c - r - d \rVert - r_c - r_d - \gamma)` (4)
   * - :math:`C \sqsubseteq \bot`, :math:`\exists R.C \sqsubseteq \bot`
     - :math:`r_c` (5), (7)
   * - :math:`C \sqcap D \sqsubseteq \bot`
     - :math:`\max(0, r_c + r_d - \lVert c - d \rVert + \gamma)` (6)
   * - :math:`C \not\sqsubseteq \exists R.D` (negatives)
     - :math:`\max(0, r_c + r_d - \lVert c + r - d \rVert + \gamma)` (10)
   * - :math:`R \sqsubseteq S`
     - :math:`\max(0, \lVert s - r \rVert - \gamma) + \left|1 - \frac{r \cdot s}{\lVert r \rVert \lVert s \rVert}\right|` (8)
   * - :math:`R_1 \circ R_2 \sqsubseteq S`
     - :math:`\max(0, \lVert s - r_1 - r_2 \rVert - \gamma) + \left|1 - \frac{(r_1 + r_2) \cdot s}{\lVert r_1 + r_2 \rVert \lVert s \rVert}\right|` (9)

Individuals are treated as nominal classes. Negatives for :math:`C \sqsubseteq \exists R.D` are
generated by replacing :math:`C` or :math:`D` by a random class (Section 3.3 of the paper).

Differences to ELEmbeddings: the unit-norm terms are inside every loss (ELEmbeddings has a
separate regularisation), the intersection loss has its fourth term, and there are the two
role axiom losses. Radii are used through their absolute value; the paper asks for
non-negative radii and mentions a penalty for negative ones without giving it.

.. warning::
   The role inclusion loss is symmetric in :math:`R` and :math:`S`, so training on
   :math:`R \sqsubseteq S` also enforces :math:`S \sqsubseteq R`, and the chain loss only
   depends on :math:`r_1 + r_2`. This is how the paper defines the losses; mOWL implements them
   as published. Chen et al. (2025) and Bourgaux et al. (2024) point this out, see the
   limitations on the catalogue card of ``emelpp``.

EmEL(var)
---------

EmEL(var) adds a learned variance :math:`\sigma(R) \ge 0` per role, so that the translated
ball may lie within :math:`\sigma(R)` of :math:`D` instead of exactly on it, and one role can
relate a class to several fillers. Only the two role losses change (Eq. 7 and 8 of the paper):

.. math::

   \max(0, \lVert c + r - d \rVert + r_c - r_d - \sigma(r) - \gamma) + \sigma(r)
   \qquad
   \max(0, \lVert c - r - d \rVert - r_c - r_d - \sigma(r) - \gamma) + \sigma(r)

(plus the unit-norm terms). The paper does not give the initial value of :math:`\sigma`, nor
how it is kept non-negative; mOWL starts at 0.1 and uses its absolute value.

.. note::
   With the weight 1 of the term :math:`+\sigma(r)`, :math:`\max(0, x - \sigma) + \sigma \ge
   \max(0, x)`: the total loss of EmEL(var) is never below that of EmEL++, so the variance
   gains nothing as printed. The option ``sigma_reg_weight`` of :class:`EmELVar` scales that
   term. It is **not** part of the paper; the default (1) is the paper's loss.

Made of parts
-------------

:class:`EmELPP` and :class:`EmELVar` (and :class:`~mowl.models.ELEmbeddings`) are combinations of
the parts of :mod:`mowl.representation`: their module is a
:class:`~mowl.representation.ComposedGeometry` that the methods ``emelpp`` and ``emelvar``
build (a ball class model, a translation relation model, the centre-distance measure, an
objective with the unit-norm terms in every axiom loss). EmEL(var) differs from EmEL++ by
exactly one part, the relation model ``translation with tolerance``, so any of the parts can
be swapped for another one (see :doc:`/representation/index`). The earlier, hand-written modules
are kept in ``mowl.baselines`` as the reference of the tests.

.. testcode::

   from mowl.nn import EmELPPModule, EmELVarModule

   for module in (EmELPPModule(3, 2, embed_dim=4), EmELVarModule(3, 2, embed_dim=4)):
       parts = module.parts
       print(parts["classes"], "|", parts["relations"], "|", parts["measure"])

.. testoutput::

   ball | translation | centre distance
   ball | translation with tolerance | centre distance

Example
-------

.. testcode::

   import torch as th
   from mowl.datasets.builtin import FamilyDataset
   from mowl.models.emelpp.model import EmELPP, EmELVar
   from mowl.nn.el.emelpp.module import EmELPPModule

   # Training. Use load_role_axioms=True for ontologies with role inclusions and chains.
   dataset = FamilyDataset()
   model = EmELPP(dataset, embed_dim=10, margin=0.0, load_role_axioms=False)
   model.train(epochs=2)
   var_model = EmELVar(dataset, embed_dim=10, margin=0.0)
   var_model.train(epochs=2)

   # The role losses directly: roles 0 and 1 are far apart, then equal.
   module = EmELPPModule(nb_ont_classes=2, nb_rels=2, embed_dim=3, margin=0.0)
   module.rel_embed.weight.data[0] = th.tensor([1.0, 0.0, 0.0])
   module.rel_embed.weight.data[1] = th.tensor([0.0, 1.0, 0.0])
   print(module.role_inclusion_loss(th.tensor([[0, 1]])).item() > 0)
   module.rel_embed.weight.data[1] = th.tensor([1.0, 0.0, 0.0])
   print(module.role_inclusion_loss(th.tensor([[0, 1]])).item())
