## [Unreleased]
### Upgrading from 2.1.0
This release removes public names and changes return shapes and default behaviour, so under the project's versioning policy (`CLAUDE.md`, "Versioning policy") it must be a **major** release (3.0.0). `tests/compat/test_v2_1_0_api.py` checks the public surface of v2.1.0 (every module, name, constructor and method signature, taken from the released code) and loads state dicts made by the v2.1.0 code.

What stays as released:
- Constructor arguments keep their positions: `FALCONModel`'s new `role_pairs`, `thing`, `nothing` come after `device`, so a positional call of 2.1.0 binds `learning_rate`, `batch_size`, `model_filepath` and `device` as before. Per-axiom loss methods take their argument by its 2.1.0 name `data`, `ELEmModule.gci2_loss` its unused third argument, and `FALCONModule.forward(axiom, x, e_emb, stage)` the stage by position.
- State dicts saved by the v2.1.0 `ELEmModule`, `ELBEModule`, `BoxELModule` and `BoxSquaredELModule` load, and these modules also save every table under its 2.1.0 name (`min_embedding.weight`, `class_offset.weight`, ...). Released attributes (`class_embed`, `min_embedding`, `class_center`, ...) are there.
- `GraphPlusPyKEENModel.train()` and `mowl.kge.KGEModel.train()` take the steps of PyKEEN's sLCWA loop as released: the memory probe, a fresh draw of every parameter at each call, PyKEEN's batches and negatives, and (on a GPU) sub-batches when a batch does not fit.

Deprecated (they work and emit a `DeprecationWarning`; each is computed by the parts and gives the 2.1.0 numbers): the loss functions of `mowl.nn.el.{elem,elbe,boxel,boxsquaredel}.losses`, `mowl.models.graph_random_walk.random_walk_w2v_model.EvaluationModel` and `mowl.models.syntactic.w2v_model.EvaluationModel`, `FALCONModule.sample_negatives` and `FALCONModule.get_cc_loss`, `BoxELModule.init_entity_embedding`, `BoxSquaredELModule.init_embeddings`, `mowl.evaluation.predictions.evaluate_predictions`.

Removed without a replacement name: the tensor-level helpers of the loss modules (`elem.losses.ball_inclusion_score`, `gci2_score`, `gci2_score_neg`; `elbe.losses.box_inclusion_score`, `gci2_score`, `gci2_score_neg`; `boxel.losses.Box`, `volumes`, `intersection`, `inclusion_loss`; `boxsquaredel.losses.box_distance`, `box_intersection`, `inclusion_score` and the `gci*_score` functions), whose formulas are measures of `mowl.representation`; the internal zero tensors `FALCONModule.nothing` and `FALCONModule.zero_emb`. `mowl.main` and `mowl.models.{elembeddings,elbe,boxsquaredel}.evaluate` could not be imported in 2.1.0 either.

Behaviour that changed, and how to get the 2.1.0 behaviour back:
- Per-axiom losses are a column `(B, 1)`: in 2.1.0 every form of `BoxELModule` and `BoxSquaredELModule` and `gci0_bot`/`gci3_bot` of `ELBEModule` were `(B,)`. `module.per_axiom_column = False`.
- A negative loss of a form that has none raises `NotImplementedError` (2.1.0 returned the positive loss). `module.strict_negatives = False`.
- `ELEmbeddings`: the loss of `C ⊓ D ⊑ E` has the fourth term of the published loss. `gci1_radius_term=False`.
- `ELBE`: the loss of `C ⊓ D ⊑ E` is one value per axiom; in 2.1.0 it was an `(n, n)` matrix that mixed axioms (a defect; no option).
- `BoxEL`: the role scale is `|s| + ε` (`positive_scale=False`); role chains compose the maps in order (`role_chain_composition="as_released"`); the box of `∃r.C` maps both corners (`gci3_preimage="as_released"`); role assertions get negatives by default (`neg_sampling_gcis=["gci2"]`).
- `FALCONModel`: `∃`/`∀` range over all pairs of entities (`role_pairs="self"`); `owl:Nothing` is the empty set (`nothing="learned"`).
- `RandomWalkPlusW2VModel` and `SyntacticPlusW2VModel`: a second `train` (and `train` after `from_pretrained`) continues from the vectors there are; 2.1.0 drew them again (`set_w2v_model(..., restart=True)`). Start vectors are seeded with a hash that is the same in every process; 2.1.0 used Python's `hash`, so a fixed `seed` gave other vectors in every process (`set_w2v_model(..., hashfxn=hash)`). OPA2Vec's annotation sentences name a class by its IRI; 2.1.0 wrote `<IRI>`, which no axiom sentence contains (`generate_corpus(..., annotation_entity_form="bracketed iri")`; `extract_and_save_annotation_corpus(..., entity_form="bracketed iri")`). A new walk replaces the walks of the previous one (`DeepWalk(append=True)`). The deprecated `EvaluationModel` gives a class without a vector the cost `inf` (2.1.0: unseeded random numbers).
- `GraphPlusPyKEENModel.reinitialise = False` (new) continues from the current parameters instead of the released fresh draw; `batching = "mowl"` (new) uses mOWL's batches, which a training regime that changes negatives or the loss needs.
- Rows of `ELDataset`/`ALCDataset`, projected edges and corpus lines are in a fixed order (sorted, then shuffled with `shuffle_seed=0`; `shuffle_seed=None` uses the global `random` module as in 2.1.0).
- `ELNormalizer` no longer corrupts the normal forms of ontologies with nested class expressions, and `EmbeddingELModel` embeds the auxiliary classes: models of such ontologies (e.g. GDA) are trained on other normal forms, and checkpoints of whole models saved with 2.1.0 for them do not load (more rows; a defect, no option).
- Datasets are downloaded to `$XDG_CACHE_HOME/mowl/datasets` instead of the working directory (`MOWL_DATA_ROOT` or `data_root=`).

### Added
- `python -m mowl.benchmarks run --gpu-memory-fraction F` caps a run at a share of the GPU memory, so that several runs can share one GPU even when one of them searches for the largest batch that fits. A benchmark implementation can name its own class for a recipe's training regime (`Implementation.regime_class`).
- `ConstructorNotImplemented` (a `ConstructorUnavailable`): a refused combination says whether it is undefined (no such combination exists) or not implemented (it exists, no formula is written).
- Volumes for more regions: `Ball.volume`, the lens of two balls (`BallLens`, what `Ball.intersect` returns now), prisms, octagon products and unions of boxes; a generic non-inclusion (`outside`) for every measure.
- `BoxEL(gci3_preimage=...)` / `BoxELModule(gci3_preimage=...)` and `Affine(preimage_reading=...)`: `"as_released"` gives the box of `∃r.C` of 2.1.0.
- `tests/compat/test_v2_1_0_api.py`: the public surface of v2.1.0 (dumped from the released code: modules, names, constructor and method signatures with parameter kinds) and state dicts made by the v2.1.0 code, checked against this version.
- The benchmark runner runs a method through a registered *implementation* (`mowl.benchmarks.implementations`; `run_benchmark(..., implementation=)`, `--implementation`, `--plugin MODULE`). `mowl.baselines.benchmarks` registers the direct implementations as `baseline` (also `python -m mowl.baselines.benchmarks run ...`), with the same recipe, regime, evaluation and seed. Results record the implementation, the recipe and every option.
- `scripts/benchmark_manifests.py` (run manifests of the full benchmark, parts and baseline, split by cost), `scripts/run_manifest.sh` and the three-way table published / parts / direct (`mowl.benchmarks.collect`, `scripts/collect_benchmarks.py`).
- Declared operations of measures and relation models (`mowl.representation.operations`), with generic definitions from the common region interface, and exact conversions between region kinds (a point as a box or ball, a box as an octagon product), so that parts of one method work in another. `docs/source/representation/swaps.rst` reports all 1,628 cross-method swaps among the region-based EL methods: 659 work with an effect, 33 are accepted but give the method's own losses on these data, 826 are refused because the combination is undefined and 110 because it is not implemented (each with the reason); none is ignored or fails.
- Joint objectives (`mowl.representation.joint_objective`, the regime `JointObjectiveSteps`): every axiom form of a step read at one draw of elements. `ComposedEL(method="grounded")` and `ComposedEL(method="faithel")` build and train with swappable parts, as does `GraphKGEModel(method="reshuffle")`.
- `TrainingRegime.step_loss`, `Accumulated` and the regime `MicroBatchAccumulation` (gradient accumulation for any model). Every optimisation step of the library runs in the shared loop; `tests/training/test_one_loop.py` enforces it.
- `QueryEmbeddingModel.score_query(search="beam"|"compile")` and the objective `AnswerMarginObjective`, from the general query search parts; `AnchorPenalty` (`mowl.training`) replaces five copies of the same term.
- `mowl/baselines/PROVENANCE.md` records, for each of the direct implementations, the file and commit it was taken from: they are the implementations as they were before the methods were rebuilt from parts.
- Every method is a combination of general parts. The named model classes (`ELEmbeddings`, `ELBE`, `BoxEL`, `Box2EL`, `TransBox`, `FALCON`, `E2R`, `Query2Box`, `DL2Vec`-style walk models, `BoxE`, `GroundedEL`, ... about 60 methods) are thin named combinations of a class model, a relation model, an individual model, a measure, an objective, regularisers, samplers, a training regime and an evaluation regime from `mowl.representation`, `mowl.training` and `mowl.evaluation`; none of them computes a loss or runs a training loop of its own. See `docs/source/representation/`.
- Any part of any method can be exchanged by name: `mowl.representation.build_method(key, classes=, relations=, individuals=, measure=, objective=, objective_options=, regularizers=, ...)` and `ComposedGeometry.replace_parts`; combinations that cannot work are refused with a message that says why (`docs/source/representation/swaps.rst` has the matrix).
- General models, one per kind of training data: `ComposedEL` (normal-form axioms), `ComposedALC` (class expressions), `ComposedSubspace` (subspace logic), `QueryEmbeddingModel` (queries), `ComposedSequenceModel` (walks and sentences), `GraphKGEModel` (triples of a projection) and `ConstructedModel` (models that are constructed, not trained).
- New kinds of parts: sequences (`ProjectionView`, `Sentences`, `Walks`, `Word2VecEncoder`, `FastTextEncoder`, ...), constructions (`FiniteModel`, `Source`, `Reading`, `Recipe`, `Guarantee`), solver programs and groundings, text encoders, manifolds, graph interactions, structural tables.
- The training loops that models had of their own are training regimes now (`mowl.training`: `ELKEmTraining`, `ConditionalStatements`, `StructuralTables`, `EdgeCorruption`, `SelfAdversarialBCE`, `AlternatingMinibatches`, `FullBatch`, `SampledLogicalLosses`, `SampledObjectiveTraining`, the triple regimes of `mowl.training.triples`, ...), each with a regime card. All models train through one loop, `mowl.training.loop.TrainingLoop`.
- `mowl.baselines`: the direct implementation of every method, with its own loss formulas, kept only for comparison. `tests/baselines` checks for every method that the combination of parts gives the same losses, the same scores and the same training run as the direct implementation, and that the named classes contain no computation of their own.
- `mowl.representation` is documented as a section of its own (`docs/source/representation/`): the idea, how to use a trained model through `geometry_of(model)` / `Model.as_geometry` (regions, `inside`, members of compound class expressions), how to combine parts (`ComposedEL(dataset, method=...)` and free combinations, the registries, `ConstructorUnavailable`), a table of which method is which combination (generated from the registries), how to add a part or a method, the rule on defaults, and the known deviations of published methods.
- Vocabulary: `OperatorFamily` (product, Goedel, Lukasiewicz, Goedel on logits) and `Representation.operators` for the fuzzy methods (FALCON, DF-ALC, Al-cone); `ClassModel.LINKED` (a class with a region in two linked spaces: EIKE, Concept2Box); `RelationModel.HEAD_TAIL_BALLS`.
- `mowl.representation`: the parts of a method as a vocabulary (`View`, `Space`, `ClassModel`, `RelationModel`, `IndividualModel`, `Construction` of and / exists / not / or, `Measure`, `Parametrisation`) and, for every catalogued method, its parts (`MethodCard.representation`, `REPRESENTATIONS`). Methods are listed by part (`list_methods(parts=..., inductive=...)`), the catalogue page has a table of the parts, and benchmarks state abilities they need (`Benchmark.requires`): the inductive knowledge graph benchmarks are only offered to methods that give embeddings to unseen names.
- Regularisation is a component of its own (`mowl.training.regularization`): penalties (`NormPenalty`, `MaxNormPenalty`, `PowerPenalty`) and projections applied after every step (`SphereProjection`, `BallProjection`, `IntervalProjection`) on chosen embedding tables, applied to any model of the generic EL loop by the regime `Regularization`, in addition to or instead of the regularisation term of the model's module (`keep_default=False`). Training regimes get the hooks `regularization` and `after_step`.
- Benchmarks of the publications of the newly implemented methods, each with its dataset, evaluation regime, published numbers and recipes: the WordNet noun hierarchy (`wordnet-noun-closure-*`, `WordNetNounClosureDataset`, `EdgeClassificationF1Regime`); knowledge graph completion on FB15k-237 and WN18RR (`kg-*-link-prediction`, `KnowledgeGraphDataset`, `KGLinkPredictionRegime`); inductive knowledge graph completion (`kg-inductive-*`, `InductiveKnowledgeGraphDataset`, `InductiveSampledRankingRegime`); the released query sets of the query embedding papers (`query-*`, `QueryAnsweringDataset`, `ReleasedQueryAnswering`); the two-view data of EIKE and Concept2Box (`yago39k-*`, `joie-dbpedia-*`, `YAGO39KDataset`, `JOIEDBpediaDataset`, `TripleClassificationRegime`, `AssertionLinkPredictionRegime`); masked ABox revision of DF-ALC (`dfalc-revision-*`, `DFALCRevisionDataset`, `MaskedABoxRevisionRegime`); the family benchmark of the FaithEL code (`faithel-family-assertions`); and the evaluation of BoxSEL on Statistical EL ontologies (`boxsel-sel-*`; the paper's ontologies are not released, so its numbers are recorded but cannot be reproduced).
- `EvaluationRegime.initialise_model(model, dataset)`, called by the benchmark runner before training, for evaluations that fix the model's starting point (a masked grounding, a set of conditionals).
- The query embedding models train on released training queries (`queries="released"`); `Reshuffle` gets `inductive_costs`, `early_stopping` and `inverse_triples`; `EIKE` reads its text vectors from a file (`save_intensional_vectors`, `load_intensional_vectors`, `pca_vectors`); `FilteredRankingRegime` ranks object property assertions.
- `mowl.logic.WorldAssumption` (`OPEN`, `CLOSED_ENTAILED`, `CLOSED_STATED`): what a regime takes an axiom to be that is neither stated nor refuted. Regime cards state it (`RegimeCard.assumption`: where negatives come from, which candidates count as wrong), benchmarks take it from their evaluation regime (`Benchmark.assumption`, `list_benchmarks(assumption=...)`), and method cards state the assumption of the method's own objective (`MethodCard.assumption`). The `query-answering` task says that it asks for certain answers (open world) and that the query answering benchmarks of the knowledge graph literature are closed world, with negation as absence of an edge.
- Training regime compatibility is declared and enforced: a model lists the regime hooks its training loop consults (`training_hooks`), a regime reports the hooks it overrides (`TrainingRegime.overridden_hooks`, `mowl.training.unsupported_hooks`), and assigning a regime that a model's loop would ignore raises `TypeError`. The query embedding models take optimiser, schedule and stopping regimes.
- The 21 newly implemented methods state their language, tasks, the training and evaluation regimes of their publications and the world assumption of their objective on their cards.
- Every method that had only a catalogue entry now has code. All are adaptations to ontologies; each card states which axiom forms are used and what differs from the paper.
- Order and hierarchy embeddings of the subclass order between named classes (`gci0` only, subsumption task): `OrderEmbeddings`, `BoxLattice`, `GumbelBox`, `HyperbolicCones`, `ShadowCones` (four formulations) and `DiskEmbeddings` (hyperbolic, spherical, Euclidean), with a small Riemannian SGD in `mowl.nn.order`.
- Query embeddings `Query2Box`, `BetaE`, `ConE` and `AConE` with a shared layer that turns a class expression into a query operator tree (`mowl.nn.query`), class-expression query answering (`model.answer`) and `score_query` for the query-answering regime.
- Region-based knowledge graph embeddings on the projected ontology, built from parts: `BoxE`, `ExpressivE`, `Reshuffle` (their direct implementations, PyKEEN's models, are in `mowl.baselines`), and `Concept2Box` (concept boxes and entity points). `BoxE`, `ExpressivE` and `Reshuffle` draw their parameters once from their `seed` and continue at every `train()`, as the published methods train once from one initialisation (`reinitialise=True` draws them again). `GraphPlusPyKEENModel` gets `num_negs_per_pos`, `reinitialise` and `batching`.
- `DFALCModel` (differentiable fuzzy ALC over a finite domain, hierarchical and rule-based losses), `EIKE` (ellipsoid concepts, point instances; language-model vectors are an optional input) and `BoxSEL` (box embeddings of Statistical EL with probabilistic conditionals `Conditional(D, C, l, u)`).
- `FaithEL` (fixed strongly faithful convex TBox, learned ABox; follows the authors' code), `mowl.geometric.StronglyFaithfulModel` with `check_strong_faithfulness` (the canonical model of Lacerda et al., Definition 26) and `mowl.geometric.ConvexRegionModel` (convex model of any finite model, Gutiérrez-Basulto and Schockaert, Proposition 3).
- `mowl.geometric.temporal_cones` (cone models of role-free LTL_ALC from finite repeating models) and `mowl.geometric.attributed` (convex models of ground attributed ontologies, read from Python objects or OWL axiom annotations).
- Joint benchmarks for comparing all methods on common data: `common-{galen,go,anatomy}-subsumption-prediction`, `-existential-prediction`, `-subsumption-inference` and `common-{yeast,human}-ppi`, all with one evaluation regime (`common-filtered-ranking`: filtered ranks, average ranks for ties, the same candidates for every model). `mowl.benchmarks.comparison.compare_methods` / `methods_table` and `python -m mowl.benchmarks compare-methods BENCHMARK` / `table` run every method whose declared tasks and expressivity match a benchmark and tabulate the results; failures are recorded per run and finished runs are reused from the output directory. Every method has default settings on the joint benchmarks (recipes with source `mowl-common`; a publication's settings are reused where it trained on the same data).
- One scoring interface for all model families (`mowl.evaluation.model_scoring`): a model declares `axiom_scoring` (`"module"`, `"evaluation_model"`, `"method"` with `axiom_costs(gci_name, rows)`, or `"vectors"`) and `scored_forms`, and `scoring="auto"` of every ranking regime uses it. Added `axiom_costs` to the ALC models (FALCON, al-cone), E2R, `GraphPlusPyKEENModel`, HiT/OnT and BoxLitE. `PairClassifierHead` (regime card `pair-classifier-head`) scores candidate axioms for models that give class vectors only (DL2Vec, OWL2Vec*, Onto2Vec, OPA2Vec, taxonomy walks); `scoring="pair_classifier"` uses it with any model.
- The benchmark runner builds and trains ALC, quantum-logic, graph and corpus models (`mowl.benchmarks.families.ScoredModelFamily`). `MethodCard.factory` names a function that builds the configured model for methods that are a configuration of a general class (default factories in `mowl.benchmarks.families` for `dl2vec`, `owl2vec_star`, `taxonomy_walks`, `onto2vec`, `opa2vec`, `graph_kge`), and `MethodCard.head_tasks` lists the tasks a vector-only method reaches through a scoring head.
- Benchmarks are linked to the tasks of `mowl.logic`: every `Benchmark` states its `completion_tasks` (the form of the ranked candidates), `encodes` (a task posed in another form, e.g. link prediction as `C ⊑ ∃r.?`), `inference_tasks`, `target` (deductive inference, inductive prediction, logical status) and the key of its `evaluation_regime` card; a test checks that card and benchmark agree. `list_benchmarks(task=, completion_task=, inference_task=, target=, method=)`, `mowl.benchmarks.supports`, `missing_support`, `methods_for` and `benchmarks_for` match methods and benchmarks by declared inference tasks and expressivity; `python -m mowl.benchmarks list --task/--target/--method` and `methods BENCHMARK`. `CompletionTask.needs` names the constructs a candidate form uses.
- Added `GroundedEL` (`mowl.models.GroundedEL`, `mowl.nn.el.grounded`): an element-grounded multi-box model of EL++ trained without a reasoner, with product or translation roles, inverse roles, exact initialisation from a least model, and logical query answering (`mowl.nn.el.grounded.queries`: box algebra and beam search for the query types 1p-3p, 2i, 3i, 2u, ip, pi, up). Catalogue cards `grounded` and `least_model` with expressivity, inference tasks and tested guarantees; documentation page `methods/grounded`.
- Added GroundedEL's training design as shared training regimes: `mowl.training.TemperatureAnnealing`, `LinearDecay`, `IdleComponentReseeding`, `LagrangianDualWeights` (and `dual_ascent_step`), and their composition `GroundedELTraining` (regime cards `temperature-annealing`, `linear-lr-decay`, `idle-component-reseeding`, `lagrangian-dual-weights`, `grounded-el-training`). `GroundedEL.train` now runs through the regime hooks; without an assigned regime it trains exactly as before. Corrupted facts can be drawn and filtered by the shared negative regimes (e.g. `KnownPositiveFilter`). `MultiBoxEL.reseed_components` makes the re-seeding regime usable with MultiBoxEL.
- Added the evaluation regime `mowl.evaluation.LogicalQueryAnswering` (card `query-answering`, previously catalogued only): filtered ranking of the hard answers of one-hop and multi-hop queries, with `sample_queries` and `answer_query`; the complete facts may be held out (prediction) or entailed (inference). Models take part through `score_query(structure, queries)`; `GroundedEL.score_query` provides it.
- Added the training-regime hook `on_epoch_end(epoch, losses)`, called after the optimisation step of every epoch by the generic EL loop and by GroundedEL.
- Packaged the Kobayashi-MaRust (KM) reasoner 1.6.5 (`kobayashi-marust-protege5-1.6.5.jar`, with Gson 2.11.0) as the reasoner backend `km`, preferred to HermiT beyond the EL family. `mowl.init_jvm(memory, extra_classpath=...)` and `MOWL_EXTRA_CLASSPATH` add further JAR files.
- `BoxSquaredEL(load_role_axioms=True)`: the role inclusion and role chain losses of the Box²EL paper, which mOWL's implementation lacked.
- `mowl.logic`: description logic expressivity in standard notation (`Expressivity`, `Construct`; `Expressivity.parse("ELH(∘)⊥ with ABox")`), the expressivity an ontology uses (`ontology_expressivity`) and the check of an ontology against what a method supports (`check_ontology`, `ExpressivityReport`). Every catalogued method states its `expressivity`; every model checks its training ontology when it is created and warns about axioms beyond it (`Model.check_expressivity`, `Model.expressivity_report`).
- `mowl.logic.tasks`: the standard inference tasks (subsumption, classification, satisfiability, consistency, instance checking, realization, ...), their reduction to subsumption tests, the completion tasks of knowledge graph and knowledge base completion, and `LogicalStatus` / `FaithfulnessCriterion`. Method cards list the `tasks` they score, evaluation regime cards the `task` and `target` they measure; `list_methods(task=..., covers=...)`.
- `mowl.reasoning`: reasoner backends chosen by expressivity (`create_reasoner`, `select_reasoner`, `register_reasoner`; ELK, HermiT and the structural reasoner are registered) and `SubsumptionOracle`, which answers inference tasks and the logical status of a candidate axiom through subsumption between class expressions.
- Explicit training and evaluation designs behind the Box²EL and TransBox numbers:
  `mowl.training.SlackMargin` / `StrictMargin` (the margin set by meaning; modules declare
  `margin_semantics`), `mowl.training.Box2ELCodeTraining` / `TransBoxCodeTraining` (the
  training design of the reference code), `TransBoxNormalFormRankingRegime` with the
  `transbox-*-prediction` benchmarks (the TransBox paper's numbers moved there), the
  scoring `centre_distance_zero_empty`, and reference test-time scorers for TransBox,
  BoxEL and EmEL++.
- `mowl.benchmarks.Recipe`, `get_recipe`, `list_recipes` and `run_benchmark(recipe=...)` /
  `--recipe`: train a method the way a publication did. `--training-regime` can be
  repeated and takes constructor arguments (`key:{json}`).
- Training designs of further reference implementations as named regimes with recipes:
  `ELKEmCodeTraining`, `EmELppCodeTraining`, `RegDCodeTraining`, `DELECodeTraining`
  (`DELECodeLosses`), `OnTCodeTraining`, `HiTCodeTraining`, `kbc-code-training` (CatE), and

  `FixedNegatives`, `JointNormalisedInitialisation`, `UnboundedNegativeLoss`,
  `PerAxiomNormPenalty`). `TransBox(formulation="reference")` follows the TransBox code.

  the ORE1 recipe uses the norm p=1 (the default of the reference run script).

DELE function prediction ranks the reference code's candidate classes.
- `mowl.training.EarlyStopping`: end training when a validation quantity stops improving (the regime `early-stopping`, previously catalogued as not implemented).
- `AGENTS.md`, a guide for AI coding agents to the layout of methods, training regimes, evaluation regimes and benchmarks, and a reproduction status page in the documentation (`docs/source/benchmarks/reproduction.rst`).
- RegD: the evaluation reproduces the reference code's prediction-task positive score
  exactly and also reports the corrected `f1_pair`; recipes with learning rate and depth
  weight chosen by validation F1.
- Recipes can be selected by name within a publication (`--recipe mashkova2024:+l`).
- Added `mowl.geometric.least_model`: sparse fixed-point and literal LP solvers for the least model over GroundedEL's indexed syntactic domain, an independent finite-model checker, and a one-dimensional interval realisation.
- Added the `GALENJackermeier2024Dataset`, `GOJackermeier2024Dataset` and `AnatomyJackermeier2024Dataset` builtin datasets: the GALEN, GO and ANATOMY ontologies with the 80/10/10 subsumption prediction split distributed with the Box²EL reference implementation, also used by TransBox (WWW 2025). The class IRIs of the Anatomy dataset are opaque generated IRIs, because the reference benchmark ships no class names for ANATOMY [#157][i157].
- Added extraction of the two EL++ role axiom normal forms — role inclusion (`R ⊑ S`) and role chain (`R ∘ T ⊑ S`, which is also how transitive property declarations are represented). New `RoleInclusion` and `RoleChain` axiom classes and an `extract_role_axioms()` function in `mowl.ontology.normalize`; new `RoleAxiomDataset`, `RoleInclusionDataset` and `RoleChainDataset` in `mowl.datasets.el`. Role axioms over non-atomic property expressions (e.g. inverses) are skipped with a warning, as are chains of more than two properties [#157][i157].
- Added a `load_role_axioms` argument to `ELDataset` and `EmbeddingELModel`, defaulting to `False`. When enabled, `get_gci_datasets()` also returns the `role_inclusion` and `role_chain` datasets; when left at the default nothing changes for existing code, including for the shipped ontologies that do contain role axioms (PPI yeast, for instance, has 3 role inclusions and 6 role chains) [#157][i157].

- Fixed the EmEL++ ANATOMY dataset being unparsable: the released file contains role chains without roles, which are now dropped when the dataset is built.

- Fixed dataset building crashing on assertions about anonymous individuals; they are skipped with a warning.
- Fixed `BoxEL`'s loss for `∃r.C ⊑ D` (the mapped upper corner of the box of `C` was read as a log-width; `gci3_preimage="as_released"` restores it), and `BaseRankingEvaluator` comparing CPU tensors with
  GPU indices when evaluating on a GPU.
- Fixed `EmbeddingELModel._load_datasets` not passing `individual_index_dict=self.individual_index_dict` when constructing the training, validation, and testing `ELDataset` instances. Previously, each split built its own individual index from only the individuals occurring in that split's ontology, whereas `model.individual_index_dict` is sorted over the union of individuals across all splits (`dataset.individuals`). Consequently, validation and testing `class_assertion` and `object_property_assertion` tensors — and the training split as well whenever validation or testing introduced individuals absent from the training ontology — indexed individuals inconsistently with `model.individual_index_dict` and the module's individual embedding table; checkpoints saved with earlier versions on datasets with held-out individuals have permuted individual embedding rows.
- Fixed `ELNormalizer` corrupting the normal forms of every ontology with nested class expressions. The jcel normaliser was given a second, fresh `IntegerOntologyObjectFactoryImpl` whose entity counter restarted at the first usable identifier, so the auxiliary classes it introduces to flatten nested expressions received the integer identifiers of named classes of the ontology. On reverse translation each auxiliary class became an unrelated named class, and axioms with auxiliary identifiers beyond the named range were dropped silently. For example, `B ⊓ ∃r.C ⊑ A` became `∃r.C ⊑ B` and `B ⊑ A` instead of `∃r.C ⊑ X` and `B ⊓ X ⊑ A`; on the Pizza ontology the normalised TBox made 35 named classes unsatisfiable instead of 2. **Models trained with earlier versions on ontologies with nested class expressions (e.g. the GDA datasets) were trained on these corrupted normal forms.** The normaliser now shares the translator's factory, names auxiliary classes and object properties `http://mowl.borg/aux/<tag>#AuxiliaryEntity<n>`, where `<tag>` is derived from the SHA-1 of the preprocessed input TBox (names are stable for an ontology, and identical preprocessed TBoxes share the same namespace), and raises instead of dropping an axiom it cannot translate back. Normal forms that are not GCIs (functional object properties, ranges) are skipped with a warning. The on-disk cache is now `<ontology>_mowl_el_normalized_v2.owl`, so existing caches with corrupted normal forms are no longer read and are recomputed.
- Fixed `ELNormalizer` silently replacing inverse roles: jcel represents `r⁻` by an auxiliary object property unrelated to `r`, so `A ⊑ ∃r⁻.B` became `A ⊑ ∃AuxiliaryEntityN.B`. Axioms using `ObjectInverseOf` are now dropped by `preprocess_ontology` like the other unsupported constructs, which are counted (`ELNormalizer.num_dropped_axioms`) and reported in one warning.
- Fixed EL models not having embeddings for the auxiliary classes of the normal forms: `EmbeddingELModel` now normalises the training ontology eagerly, once, at construction, and appends the auxiliary classes and object properties to `class_index_dict` and `object_property_index_dict` after the dataset entities, whose indices are unchanged. Consequently `class_embeddings` and `object_property_embeddings` now include auxiliary keys, and checkpoints saved with earlier versions will not load into models of ontologies with nested class expressions (the embedding tables have more rows). `dataset.classes` and the evaluation classes are not modified, so auxiliary classes are never ranking candidates, and the `"classes"` negative sampling pool contains named classes only (`named_class_index_dict`). `ELDataset` skips axioms that mention entities missing from given index dictionaries (e.g. auxiliary classes of a validation or testing ontology) with one warning giving their number, instead of raising `KeyError`.
- Fixed `ELBE`'s `gci1_loss` returning an `(n, n)` matrix instead of one loss per sample. It added a column of shape `(n, 1)` to a flat vector of shape `(n,)`, which broadcasts, so every GCI1 score was combined with every other sample's score and the loss minimised was not the intended one. Training still ran, because the mean of the matrix is a scalar. The bug dates from 2023 and was invisible to the tests, which only ever passed single-row batches, where `(1, 1)` and `(1,)` broadcast to `(1, 1)`. `ELEmModule` and `BoxSquaredELModule` were checked and are unaffected.
- Fixed `RemoteDataset._download` hanging forever on a connection that goes silent mid-transfer. `requests` has no default timeout, so a stalled socket never raised; the request now sets a connect and read timeout and retries with backoff [#149][i149].
- Fixed an interrupted download leaving a truncated tarball that later runs mistook for a complete one. The transfer now writes to a temporary file and is renamed into place only once it finishes [#149][i149].

- Bumped CI GitHub Actions (setup-java, setup-python, checkout, upload-artifact, download-artifact, github-script, sigstore, conda setup-miniconda).
- Raised build requirements to `setuptools >=83.0.0` and `setuptools-scm >=10.2.1`.
### Removed
- Removed ontology load caches that polluted shared test fixtures.
### Fixed
- Fixed `BaseRankingEvaluator` scoring the wrong entities when the evaluation pool is a subset of the ontology's classes. The swept column carried pool positions where the evaluation model expected global entity ids, so `GDAEvaluator`, `PPIEvaluator` and `SubsumptionEvaluator` silently produced meaningless ranking metrics [#146][i146].
- Fixed the ALC documentation doctest by dropping empty `testoutput` blocks.
- Repaired the `ELEmbeddings` and `ELBE` gallery examples, which had not been updated for the 2.0.0 API and could not run: `epochs` was passed to `__init__` instead of `train()`, and the ELBE example still imported `ELBoxPPI` from the removed `mowl.models.elboxembeddings` module. Their published evaluation metrics have been regenerated.

## [2.0.0] - 2026-05-12
### Added
- Added caching support for `ELNormalizer`: normalized ontologies can now be saved to disk and loaded on subsequent runs, significantly speeding up repeated normalization of the same ontology.
- Added `ontology_path` and `use_cache` parameters to `ELNormalizer.normalize()` and `ELDataset`.
- `EmbeddingELModel` now automatically uses caching when the dataset provides ontology paths (e.g., `PathDataset`).
- Added `BoxSquaredELGDA` and `BoxSquaredELPPI` model classes.
- Added `evaluate_ppi()` convenience method on PPI models (`ELBEPPI`, `ELEmPPI`).
- Added `neg_capable_gcis` property to `ELModule`; negative sampling now extended to all non-bot GCIs.
- Added tests for EL models (ELBE, ELBEPPI, ELBEGDA, ELEmGDA, BoxSquaredEL).
### Changed
- Refactored EL model training loop: `train(epochs, validate_every=1)` now has a standardised signature across all EL models.
- `eval_gci_name` is now a validated property on `EmbeddingELModel`; it must be set explicitly before calling `train` with validation or `evaluate`.
### Removed
- `ELBoxEmbeddings` alias removed. Use `ELBE` directly.
- `epochs` parameter removed from EL model `__init__`. Pass `epochs` to `train()` instead.
### Fixed
- `ELBEPPI` now automatically sets `PPIEvaluator` in `__init__`, matching `ELEmPPI` behavior.
- Fixed `evaluate_ppi()` in `ELBEPPI` and `ELEmPPI` to pass required `testing_ontology` argument.

## [0.1.0]

### Added
- Modules `mowl.ontology.extend` and `mowl.ontology.create` created including `insert_annotations` and `create_from_triples` methods, respectively.
- Package `deprecated` as dependency.
- ELEmbeddingModel abstract class that contains basic functionality for models embedding the EL language.
- Implementation of [ELBoxEmbeddings](https://arxiv.org/abs/2202.14018)
- ELDataset class to work with EL models.
- Module `mowl.nn` where `torch.nn`-based modules will reside. The first module existing there is the abstract module for EL models.
- Module `mowl.models` where implementation of ELEmbeddings and ELBoxEmbeddings reside.
- PyKEEN as dependency
- `GDAHumanELDataset` and `GDAMouseELDataset`, which are reduced versions of `GDAHumanDataset` and `GDAMouseDataset`, respectively. The new datasets can be normalized into the `EL` language using the [jcel](https://julianmendez.github.io/jcel/) library.
- Started implementation of unit tests for `datasets` and `walking` modules.
### Changed
- All builtin datasets can be imported from `mowl.datasets.builtin` module.
- Updated implementation of [ELEmbeddings](https://www.ijcai.org/Proceedings/2019/845)
- Changed method `mowl.datasets.PathDataset.get_evaluation_classes` to property `mowl.datasets.PathDataset.evaluation_classes`
- #25 Walking methods now accept an optional parameter for a list of nodes to filter the random walks.

### Deprecated
- Modules `mowl.datasets.ppi_yeast` and `mowl.datasets.gda`.
- File `mowl.datasets.build_ontology`.
- Class `mowl.embeddings.elembeddings.ELEmbeddings`. Future versions will point to `mowl.models.ELEmbeddings`
- Method `mowl.corpus.base.extract_annotation_corpus`. Future versions will split this method into two: `mowl.corpus.base.extract_annotation_corpus` and `mowl.corpus.base.extract_and_save_annotation_corpus`.
- Method `mowl.datasets.PathDataset.get_evaluation_classes`.
